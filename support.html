TROUBLESHOOTING

问题排查

遇到问题时，先确认路径、账号、网络和任务日志，再根据现象定位。下面的顺序适合大多数部署环境。

四步排查法

1. 看容器

确认容器状态为 Up，没有反复重启或端口冲突。

2. 看路径

在容器内确认 /config、/media、/CloudNAS 是否存在且权限正确。

3. 看账号

检查 115、CloudDrive2、PT 或通知凭据是否过期。

4. 看任务

打开任务详情和日志，记录失败步骤与原始错误信息。

常见问题

页面打不开

先确认访问的是服务器 IP 和正确端口。桥接网络检查端口映射，host 网络检查宿主机端口是否被占用。

CloudNAS 目录为空

检查 CloudDrive2 是否已经挂载、共享传播是否开启，以及 DIAN115 是否映射了同一个容器路径。

整理任务失败

查看任务日志中的源路径、目标路径和写入权限。先用单个文件测试规则，再恢复批量任务。

Emby 扫描不到文件

对比 DIAN115 与 Emby 的容器内路径。两边都应使用 /media/...，不要混用宿主机绝对路径。

通知没有发送

重新验证 Bot Token、Chat ID 或 Webhook，确认事件条件确实满足，并检查网络出口。

日志与反馈

收集问题时请提供版本号、部署方式、复现步骤和脱敏后的日志片段。不要上传账号 Cookie、Token、二维码或完整配置文件。

collect logs
docker compose ps
docker compose logs --tail=200 dian115

可以在 GitHub 仓库提交 Issue，或先在通知模板和参考手册中查找相关字段。

维护建议

  • 升级前备份 /config。
  • 定期检查任务队列中是否有长期失败任务。
  • 清理缓存前确认没有批量整理正在运行。
  • 每次修改路径后，用小范围任务做回归验证。
