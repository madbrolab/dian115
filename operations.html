12

容器更新

DianCupLite 在不使用特权模式的前提下管理本机其他容器。

入口：容器更新

挂载 Docker Socket 后，DianCupLite 能读取容器和镜像摘要，检查远端更新，按队列执行手动或定时更新，并提供运行状态与资源视图。

检查与更新按容器检查本地/远端摘要，标记可更新、最新或失败，更新过程显示阶段与百分比。
运维控制查看 CPU、内存和镜像，执行启动、停止、重启，并保存容器别名与图标。
镜像管理浏览镜像、关联容器与大小，安全清理悬空镜像和 DianCupLite 备份镜像。
定时策略与安全边界
  • 支持 Cron 调度、是否包含停止容器、检查并发、停止超时与通知策略。
  • 私有仓库、没有 RepoDigest 的本地镜像或网络异常可能只显示检查失败，不会盲目更新。
  • 更新队列运行时，镜像删除与清理暂时禁用，以免破坏回滚点。
  • 只需要 /var/run/docker.sock，不需要特权模式和宿主机根目录映射。
!

更新会造成短暂停机。媒体扫描、数据库写入、做种和分享任务运行时不要批量更新；先备份配置，再逐个验证关键服务。

全局缓存与 FFP 缓存

减少重复外部请求，让同一 SHA1 的媒体信息跨功能复用。

入口：全局缓存
缓存保存内容主要价值
TMDB媒体元数据与海报索引加快探索、订阅与识别。
115 分享分享码、质量与有效性避免反复解析，跟踪失效状态。
TG 监控分享频道采集的分享链接频道去重、资源状态和订阅复用。
离线链接磁力与 ED2K 记录避免重复提交与解析。
FFP-cache按 SHA1 索引的容器、媒体流、章节与技术字段整理、洗版、ED2K、画像与远端上报复用。

FFP-cache 的工作方式

  • 来源区分本地上报、FFP 探测缓存与 Madby 读取缓存，可按来源筛选。
  • 读取采用本地优先；远端命中写回本地，同一 SHA1 后续直接复用。
  • 低完整度信息不会覆盖高完整度信息；页面显示命中、冲突和上报状态。
  • 批量整理可预取缓存，减少每个候选单独执行 ffprobe 的成本。
  • 删除缓存不会删除真实媒体，但待上传队列中的对应项会同步清理。
i

缓存不是数据源。当媒体路径、站点认证或分享内容已变化时，刷新对应缓存再验证，不要用“清空全部缓存”代替配置排查。

14

门户功能

为家庭、朋友或小型社区提供独立用户入口与运营后台。

入口：门户总控

门户把管理员和终端用户分开。管理员维护用户、共享/独享 115 账号、邀请码、求片、工单、数据健康和社区；用户通过门户完成播放、请求与账户操作。

账号中心共享/独享模式、用户有效期、115 账号池、CK 检查、播放缓存和一次性邀请码。
服务中心求片申请、工单分类、状态流转、管理员回复与站内消息广播。
数据与社区用户分析、健康、审计、签到、积分、徽章、成就、榜单、评分、帖子与投稿。
邀请码与账户模式

管理员可生成共享或独享模式邀请码。当前实现为固定 14 位、一码一用、4 天有效。共享模式复用池账号；独享模式由用户绑定自己的 115 账户，配额与风险隔离不同。

!

门户涉及用户账号、115 CK、播放缓存、工单和社区内容。对外开放前使用 HTTPS、强密码、最小端口和定期备份，管理后台不要共享弱口令。

音乐代理与播放器

把 115 音乐目录映射到 Navidrome / Subsonic，并在 DIAN115 内直接播放。

入口：我的媒体 → NAVIDROME

音乐代理

  • 配置 Navidrome 后端、Subsonic 用户名/密码和独立代理端口。
  • 选择主账号对应的 CD2 音乐源路径与本地软链接路径。
  • 支持实时监听 115 生活事件、定时增量或全量同步。
  • 支持 302 失败回退本地代理，以及删除时清理软链接和空目录。

音乐树与播放器

  • 构建全量目录树、增量同步、同步 Navidrome 歌曲 ID 并生成符号链接。
  • 统计音乐总数、已匹配和未匹配歌曲，任务显示进度与日志。
  • 悬浮播放器支持音乐库、完整播放页、队列、进度和基础控制。
  • 播放器从页面右侧“点点”综合助手进入。
i

音乐树只使用主账号云盘。CD2 路径必须与“账号配置 → 扩展设置”中的主账号云盘一致。

16

AI 助手

既能解释系统状态，也能在授权范围内调用 DIAN115 管理工具。

入口：点点 → AI 助手

AI 助手与会话助手和音乐共享浮动入口，支持流式回复、推理过程、工具进度、Markdown、复制、停止生成、新会话与本地历史。

管理模式读取系统状态并调用账号、订阅、任务、PT、整理和后台 API；危险动作需要确认。
闲聊模式适合解释概念、整理思路和普通问答，减少不必要的管理工具调用。
TG 助手网页与 Telegram 助手共用提供商池，可按使用位置选择不同模型和允许工具。
模型与提供商
  • 支持 OpenAI 兼容协议，在 Chat Completions 与 Responses 中二选一。
  • 支持多个提供商、模型列表、上下文上限、温度、Top P、Tool Choice、并行工具和超时。
  • 网页助手、TG 助手、媒体整理与 AI 字幕可分别指定 provider / model。
  • 上下文达到限制后按完整对话轮次整理旧消息，避免切断工具链。
GitHub 与仓库工具

配置 Fine-grained PAT 后，AI 可在 /dian115AI 工作区拉取、检查、修改、暂存、提交和推送仓库，也可访问 Issue、PR、Release 与 Actions。Token 只交给后端加密保存，不应进入 AI 上下文、Git URL、命令参数或日志。

!

管理模式具备真实操作能力。不要要求 AI 输出 Cookie、Token、密码、安全码或 API Key；后台工具会脱敏并排除高风险通用接口。

17

更多常用能力

除重点模块外，日常使用还会频繁用到这些能力。

更多入口

追剧日历

按日期查看订阅剧集的播出与更新，区分尚未播出、未找到、下载未完成和入库缺集。

下载管理

维护 qBittorrent / Transmission 连接和任务。先测试 WebUI、账号、默认下载器与保存路径。

任务队列

查看整理、转存、分享、秒传、字幕、STRM 与插件任务的阶段、进度和失败原因。

运行日志与网络测试

按任务 ID、规则、路径、账号和站点定位问题；依次测试代理、FlareSolverr、Telegram、TMDB 与 115。

页面入口用途
追剧日历/automation/calendar查看订阅剧集播出和更新。
下载管理/resources/downloads下载器连接、任务与保存路径。
任务队列/control/jobs后台任务进度、详情与错误日志。
运行日志/control/logs实时日志与跨功能排障。
系统设置/control/settingsCD2、代理、FlareSolverr、Webhook、AI 与安全。
i

升级后先检查新增配置项和依赖，再恢复整理、订阅、刷流等批量任务。
