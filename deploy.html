DEPLOYMENT

部署指南

使用 Docker Compose 在 Linux 主机、NAS 或 Unraid 上启动 DIAN115。先准备持久化目录，再选择网络模式和路径映射。

环境准备

推荐使用 2 核 CPU、2 GB 以上内存和 Docker Engine 24+。媒体整理和元数据任务越多，所需内存越高。

项目建议说明
操作系统Linux amd64 / arm64生产契约以 Linux Docker 为准。
存储SSD 配置目录将 /config 放在稳定、可写且会备份的卷上。
网络host 或桥接同机访问 CloudDrive2 时优先考虑 host 网络。

Compose 配置

把下面内容保存为 docker-compose.yml，将宿主机路径替换成实际目录。

docker-compose.yml
services:
  dian115:
    image: madbrolab/dian115:latest
    container_name: dian115
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./config:/config
      - ./media:/media
      - ./CloudNAS:/CloudNAS:shared
    environment:
      TZ: Asia/Shanghai
!

如果使用桥接网络，请显式映射控制台端口，并让容器通过宿主机局域网地址访问 CloudDrive2，不要把 127.0.0.1 当成宿主机。

启动容器

在 Compose 文件所在目录运行：

shell
docker compose pull
docker compose up -d
docker compose ps

看到容器状态为 Up 后，在浏览器访问 http://服务器IP:8095。首次进入会显示管理员初始化页面。

首次验收

  1. 设置管理员密码，确认页面能正常刷新。
  2. 打开配置中心，确认 /config 中已经生成配置文件。
  3. 在账号管理中完成一次 115 登录，并检查账号状态。
  4. 创建一个测试任务，确认任务队列能看到执行状态和日志。
  5. 重启容器后再次登录，确认设置和账号没有丢失。
✓

验收建议使用一个小文件或单集内容。不要在首次启动时直接运行全量媒体整理。

升级与回滚

升级前先备份 config 目录。拉取新镜像后执行 docker compose up -d，如果需要回滚，把镜像标签固定到上一版本再重新启动。

升级后优先检查任务队列、账号状态和媒体库扫描，不要只看容器进程是否为 Up。
