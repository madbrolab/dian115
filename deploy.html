部署指南

从服务部署和基础配置开始，逐步完成资源发现、订阅、整理、STRM、分享与系统维护。先把路径与持久化设计正确，再启动容器；这比启动后反复改路径可靠得多。

部署前准备

Docker 环境

Linux 主机、Docker Engine 与 Compose v2。主服务默认 8095，Emby 代理 8098，Navidrome 代理 4534；6060 仅供内网调试。

持久化目录

/config 保存数据库、配置与缓存；使用 AI 工具时持久化 /dian115AI，用于长期记忆与工作文件。更新前优先备份整个 /config。

路径可见性

推荐使用 /media 与 /CloudNAS:shared。DIAN115、CloudDrive2 与 Emby 对同一媒体的容器路径必须一致或可转换。

可选 Docker Socket

/var/run/docker.sock 只供 DianCupLite 自动更新和镜像管理；不用相关功能即可删除，不需要特权模式或宿主机根目录映射。

!

先决定路径，后创建规则。整理、STRM、Emby、Navidrome 和文件管理共同引用路径。部署后再改变映射，容易造成规则失效、重复扫描或路径无法匹配。

Docker Compose：Host 网络

Linux、NAS 与 Unraid 优先使用 Host 网络。Host 网络直接占用宿主机端口，因此不要同时保留 ports。

docker-compose.yml · 推荐 Host 网络
services:
  dian115:
    image: madbrolab/dian115
    container_name: dian115
    restart: unless-stopped
    network_mode: host
    volumes:
      - ~/config:/config
      - ~/dian115AI:/dian115AI
      - /var/run/docker.sock:/var/run/docker.sock
      - ~/media:/media
      - ~/CloudNAS:/CloudNAS:shared
i

管理后台通常访问 http://服务器IP:8095。Docker Socket 和 /dian115AI 都是按功能选用，但 /config 必须持久化。

Docker Compose：桥接网络

不支持 Host 网络或需要反向代理统一入口时，使用桥接网络并显式映射端口。桥接与 Host 两种写法二选一。

docker-compose.yml · 桥接网络
services:
  dian115:
    image: madbrolab/dian115
    container_name: dian115
    restart: unless-stopped
    ports:
      - "8095:8095"
      - "8098:8098"
      - "4534:4534"
    volumes:
      - ~/config:/config
      - ~/dian115AI:/dian115AI
      - /var/run/docker.sock:/var/run/docker.sock
      - ~/media:/media
      - ~/CloudNAS:/CloudNAS:shared
    environment:
      - PORT=8095
      - TZ=Asia/Shanghai
      # - DIAN115_HTTP_PROXY=http://代理服务器IP:7890
项目默认值用途与注意
主服务8095Web 管理、API 与插件入口，可用 PORT 修改。
Emby 代理8098反向代理与播放重定向；页面改端口后 Compose 映射也要同步。
Navidrome 代理4534不用音乐代理时无需暴露。
调试端口6060pprof / 调试，仅在明确排障时向内网开放。
数据目录/config数据库默认位于 /config/dian115.db，必须持久化。
媒体 / CD2/media、/CloudNAS与 Emby、CD2 路径保持一致；CloudNAS 保留 :shared。
启动与检查
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=200 dian115

FlareSolverr 过盾工具

UIndex 等资源站可能触发 Cloudflare 验证。只有使用这类站点时才需要单独部署 FlareSolverr，然后在系统设置的基础或代理配置中填写服务地址并测试。

docker-compose.yml · FlareSolverr
services:
  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    restart: unless-stopped
    ports:
      - "8191:8191"
    environment:
      - LOG_LEVEL=info
      - LOG_FILE=none
      - LOG_HTML=false
      - CAPTCHA_SOLVER=none
      - TZ=Asia/Shanghai
    volumes:
      - ./flaresolverr:/config
部署关系DIAN115 中填写说明
同一 Compose 桥接网络http://flaresolverr:8191推荐，容器名可直接解析。
DIAN115 使用 Host，同一宿主机http://127.0.0.1:8191 或服务器 IP只有同机 Host 网络才适合 127.0.0.1。
部署在不同机器http://FlareSolverr机器IP:8191确认防火墙放行，尽量只允许内网访问。
!

桥接网络中的 127.0.0.1 只指向 DIAN115 容器自己，不代表宿主机或 FlareSolverr。首次请求启动浏览器环境可能较慢，8191 不要暴露公网。

首次启动与验收

  1. 打开管理界面访问 http://主机IP:8095。首次使用会要求设置管理员密码，没有需要猜测的默认密码。
  2. 完成授权激活如果授权守卫提示激活，填写收到的 License Key；发码与核对方式见“捐赠、激活与排障”。
  3. 立即完成安全设置设置强密码，需要外部访问时启用两步验证。OpenAPI Key 只在确实使用 Webhook、Madby 或外部 API 时创建。
  4. 检查容器内路径文件管理应能看到 /CloudNAS 与 /media；看不到时先修正 Compose，不要继续创建整理或 STRM 规则。
  5. 观察日志与状态确认容器没有反复重启，数据库位于 /config，端口没有冲突，页面能正常刷新。
✓

最小验收标准：重启后管理员密码、激活状态和配置仍在；文件管理能浏览映射目录；仪表板没有持续性的数据库或权限错误。

更新与回滚前检查

  • 备份宿主机的 config 目录，其中包含主数据库、分库、缓存索引与运行设置。
  • 使用 GitHub AI 工具时，同时备份 dian115AI 工作区内尚未推送的改动。
  • 更新前结束重要整理、分享、秒传、字幕或容器更新任务，避免中途重启。
  • 常规更新使用 docker compose pull 与 docker compose up -d，完成后检查健康状态与最近日志。
