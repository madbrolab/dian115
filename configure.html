CONFIGURATION

路径与配置

把宿主机目录映射为稳定的容器内路径，再按顺序接入 115、CloudDrive2、Emby 和通知服务。路径统一是自动化可靠性的基础。

容器路径规范

所有任务都以容器内路径为准。不同宿主机只需要改变左侧映射，DIAN115、CloudDrive2 和 Emby 看到的右侧路径保持不变。

容器路径用途建议权限
/config账号、数据库、日志和应用设置可读写，建议独立备份
/media本地媒体、整理输出和 STRM 文件可读写，和 Emby 保持一致
/CloudNASCloudDrive2 挂载的云端目录至少可读，按需开启共享传播

115 账号

在账号管理中添加主账号后，先执行一次连接测试。需要隔离下载或转存权限时，再添加备用账号并为任务选择对应账号。

主账号

用于分享解析、转存和离线任务。建议开启二次验证并定期检查登录状态。

备用账号

用于分担转存或下载任务。不要把多个账号指向同一个临时目录，避免状态互相覆盖。

i

账号令牌属于敏感配置。导出配置或提交问题时，先移除 Cookie、Token 和二维码内容。

外部服务接入

CloudDrive2

将挂载点映射到 `/CloudNAS`，然后在 DIAN115 中选择相同路径。目录树能展开但任务无法读取时，优先检查挂载传播和容器权限。

Emby / Navidrome

媒体服务器和 DIAN115 必须看到同一媒体文件的容器内路径。例如两边都使用 `/media/movies`，不要一边使用宿主机路径、一边使用容器路径。

Telegram 与 Webhook

通知配置只保存必要的 Bot Token、Chat ID 和 Webhook 地址。完成配置后用一个低频事件测试，避免首次接入就发送大量历史任务。

推荐配置顺序

  1. 确认 `/config`、`/media`、`/CloudNAS` 能读写。
  2. 登录 115，验证分享解析和转存。
  3. 接入 CloudDrive2，确认挂载目录可见。
  4. 配置 Emby / Navidrome 的媒体根路径。
  5. 最后配置 PT、通知和自动化规则。
