# 自定义合集补充模板

这里仅维护 TMDB 官方 Collection 未覆盖的补充分组。电影官方合集由整理时已经获取的 `/movie/{id}` 详情中的 `belongs_to_collection` 提供，不发布也不维护完整官方合集清单。TMDB 没有电视剧官方 Collection，因此电视剧可以直接使用补充词表。

## 运行优先级

1. 未开启对应媒体类型的“合集区分”：不读取任何补充词表。
2. 电影命中 TMDB 官方 Collection：使用官方名称，不读取补充词表。
3. 电影成功确认 `belongs_to_collection: null`：先查用户自定义，再查在线只读模板。
4. 电视剧：先查用户自定义，再查在线只读模板。
5. TMDB 官方状态未知时停止该电影的整理并等待重试，不能误判为官方未覆盖。

## YAML 格式

```yaml
schema_version: 1
movie:
  - name: 自定义电影分组名称
    tmdb_ids: [10001, 10002]
tv:
  - name: 自定义剧集分组名称
    tmdb_ids: [20001, 20002]
```

`movie` 与 `tv` 是独立命名空间。同一媒体类型中，一个 TMDB ID 只能属于一个分组；每个分组至少包含两个不同 ID。名称不能包含路径分隔符、控制字符或 Windows 保留设备名。

## 在线与用户自定义

- 在线模板只能预览和整体替换在线快照，接口只返回少量只读节选；确认保存时由后端重新拉取并核对内容指纹。
- 用户内容在系统设置的“自定义合集补充词表”中单独编辑和保存。
- 用户自定义与在线模板重叠时，以用户自定义为准。
- 两种补充来源都低于电影 TMDB 官方 Collection。

## 提交 PR

1. 在线模板应保持精简，只提交官方未覆盖且关系明确的补充分组。
2. 不要提交 TMDB 官方电影 Collection 的展开清单。
3. 不要猜测电视剧与电影共用 ID；必须分别填写在 `tv` 与 `movie`。
4. 提交前检查名称、ID、媒体类型和同类型归属冲突。
5. 更新模板时同步修改 [`manifest.json`](./manifest.json) 的说明。

项目不会在本地自动检查在线模板更新。只有用户主动拉取并确认后才替换在线只读快照。
