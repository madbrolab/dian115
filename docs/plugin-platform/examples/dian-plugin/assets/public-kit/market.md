# 市场规范 v3

市场索引仍使用 v3 Schema。保护材料与准入存储就绪的宿主要求新正式安装与更新采用 `protected-v4` 编译包；已登记的具体历史内容保留兼容。本机源码调试包不能上架。编译和签发已在本地实现，线上可用性须查询宿主真实环境，参见[实施状态](encrypted-delivery.md#编译-mcp-与正式发布)。

本文规定插件进入市场的要求。仓库是 HTTP/HTTPS 索引，格式见[索引 Schema](market-index.schema.json)。发布前运行：

```bash
node conformance/project-check.mjs <插件目录>
node conformance/market-check.mjs <index.json>
node conformance/audit.mjs <插件目录>
```

## 上架条目

每个版本是一条记录，缺少必填字段时，宿主会把整个仓库标记为错误。

| 字段 | 必填 | 要求 |
| --- | --- | --- |
| `id` | 是 | 与 `plugin.json` 一致；小写字母、数字、点和连字符 |
| `name` | 是 | 插件名称，不得冒充宿主或其他插件 |
| `version` | 是 | 与 `plugin.json` 一致；同一 `id` 下不可重复 |
| `author` | 是 | 正式包为签名中的会员昵称；历史包与 `plugin.json.author` 一致 |
| `description` | 是 | 说明插件做什么，不写宣传语 |
| `homepage` | 是 | 项目主页或反馈地址，HTTP/HTTPS |
| `changelog` | 是 | 本版本改了什么 |
| `source_url` | 是 | 源码或加密 `.dian115p` 包的下载地址 |
| `sha256` | 是 | 包文件的 SHA256 |
| `delivery` | 是 | `protected-v4`；历史格式 `source`、`encrypted` |
| `permissions` | 按需 | 须覆盖清单 `permissions` 的全部申请项 |
| `declared_usage` | 否 | 作者说明，不代替宿主分析 |
| `icon` | 否 | HTTP/HTTPS 图标地址，卡片按需加载，不为取图标下载插件包 |
| `repository_url` | 否 | 项目源码仓库地址；未提供时卡片链接使用 `homepage` |
| `keywords` | 否 | 搜索关键词字符串数组 |

## 宿主校验

用户选择版本后，宿主依次：

1. 下载包并核对 SHA256。
2. 对正式包核验 DIAN115 本地来源签名和内容摘要，解密后读取真实 `plugin.json`，开发者署名取签名昵称。
3. 核对 `id`、`version`、`author` 与条目一致，清单申请的权限不超出条目声明，不一致就拒绝。
4. 分析实际代码，命中禁止接口就拒绝。
5. 显示安装确认，由用户决定是否安装。

插件中心只显示“内置插件”和“用户插件”。商店由用户插件页右下角入口打开，代码和远程索引在打开时才加载。弹窗即时显示框架，各来源独立请求、完成即展示；单源超时为 20 秒，失败不会阻止其他来源展示。关闭弹窗取消在途索引请求。管理接口 `GET /api/extensions/v3/_market/catalog?repository=<已登记来源 ID>` 只读取指定来源；不带参数仍兼容原汇总返回。

来源仍是一份 v3 JSON 元数据索引，搜索、来源筛选、安装状态和版本比较不下载插件包，也不逐个拉取清单。同一来源的每个插件默认展示最高可比较版本，多个来源分别保留；数字版本与预发布版本按版本先后比较，本地版本较新时不会误报更新。非数字版本无法判断先后时显示“版本不同”，建议索引将最新版本列在前面。长列表分页渲染，图标按需加载。用户插件列表使用 `GET /api/extensions/v3?summary=1`，省略完整扫描报告；单个安装详情仍保留报告。超大仓库后续可扩展分页索引，无需为当前结构引入额外搜索服务。

右侧支持一行一个地址批量添加来源。移除来源不卸载已安装插件。

直接从地址或本地文件安装时不要求这些市场条目字段，但正式包仍须通过相同验签。直接导入源码归为本机调试；历史及调试包缺少作者时显示“未署名”。

## 安装确认

宿主先展示插件身份、版本、任务数量与简短能力风险摘要。危险操作保留在摘要中；完整接口操作、DNS 快照、代码位置与作者声明分别折叠，展开时才渲染明细。能力明细仍按危险程度分组，使用中文名称，同级内越危险越靠前，每组先显示 4 项。授权开关与侧边栏选项位于插件管理页“权限与显示”，不放在卡片上。

| 等级 | 含义 | 例子 |
| --- | --- | --- |
| 危险 | 可能删除数据、动用账号或影响系统 | 清空回收站、删除文件、用 TG 账号发消息 |
| 高 | 改动文件、规则或对外发消息 | 移动文件、转存分享、机器人发消息 |
| 中 | 写入配置或访问外部网络 | 创建离线任务、发送通知、访问外部网络 |
| 低 | 只读取信息或使用插件自己的数据 | 读取文件列表、查询状态、读写插件数据 |

路径动态拼接、无法确定的调用显示为“无法确定的宿主接口调用”，归入高等级。尽量写固定路径，例如 `` `/api/rules/${id}/sync` `` 可以识别，`ctx.api.post(path)` 无法识别。

检测结果来自静态分析，用于帮助用户判断，不是权限边界，也不限制插件运行。

安装检查的 DNS 快照通过固定 IP 直连 HTTPS 解析：优先阿里 DNS `223.5.5.5`，失败后尝试 Cloudflare `1.1.1.1`，保留 TLS 证书校验。此快照不使用系统 DNS、应用代理或环境代理，失败不会回退到系统解析；解析答案中的 `198.18.0.0/15` Fake-IP 地址会被拒绝，其他正常的 198.x 地址保留。插件代码直接写出的 IP 属于实际目标证据，原样显示。每次检查最多 4 个域名同时解析，总预算 2 秒；查询结束释放连接，失败只记入快照，不阻止其他安装检查。历史快照保留原检查时间，重新检查插件会生成新快照。

## 内容要求

- **如实描述：** 名称、说明和 `declared_usage` 须与实际行为相符。
- **权限最小：** 只申请用到的 `permissions`，说明为什么需要。
- **用户数据：** 把用户数据发往外部时，须在说明中写明目标和用途。
- **副作用：** 删除、群发、账号发消息等操作须由用户明确配置或确认，不得默认开启。
- **依赖：** 代码全部打进包内，不加载远程脚本或远程模块。
- **稳定：** 使用公开接口。未公开接口可能随时变更，不作为上架依赖。

## 安全审查

上架前运行 `audit.mjs`，结论不能是 `do-not-install`；有误报时在 `declared_usage` 说明原因。仓库维护者上架第三方插件前，应按[安全审查](security-audit.md)审查源码。

## 禁止内容

- 读取、外发或记录令牌、密码、Cookie 等凭据。
- 绕过宿主权限检查，或拼接路径规避安装扫描。
- 隐藏行为、后门、挖矿、刷量或批量骚扰。
- 冒充宿主系统通知或其他作者。
- 提交生成包、签名密钥或主项目源码到市场目录。

## 版本与下架

- 版本发布后不改内容；修复问题发新版本。
- 更新时，已授权且仍申请的权限保留，新申请的权限默认关闭。
- 仓库维护者可以移除违反本规范的条目；已安装的插件不会被自动卸载，用户需要自行处理。
