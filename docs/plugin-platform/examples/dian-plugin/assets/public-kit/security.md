# 安全限制

安装前检查恶意代码的方法见[安全审查](security-audit.md)。

插件是可信扩展，但有几类能力宿主一律不开放。规则是硬性的：不做风险评分，命中即拒绝。

## 接口使用边界

公开接口目录、OpenAPI 和 SDK 仅收录插件可调用的接口，不展示禁用接口及其路径清单。插件使用自己的数据空间，并复用宿主公开的业务能力；凭据由宿主保管。安装与平台管理操作由用户在插件中心完成。

执行方式：

1. **安装、更新时**：宿主扫描页面和后台代码，命中受限调用即拒绝，并指出文件和行号；仅按请求方法限制的操作在运行时检查。
2. **运行时**：后台 `ctx.api` 与页面 SDK 请求继续接受宿主权限检查，拒绝时返回 403。
3. **宿主启动时**：已安装插件按当前规则复查，违规的停用。

开发时用 `node conformance/project-check.mjs <插件目录>` 检查清单、入口和源码结构；权限检查由宿主在安装和运行时完成。本地结构检查通过不代表宿主一定接受安装。

## 消息渠道

Telegram 机器人、企业微信和 TG 监控账号由宿主代为调用，插件拿不到令牌、密钥和渠道配置。账号能力须用户逐插件授权；@BotFather 与 Telegram 登录通知账号对插件不可见，避免经账号取得 Bot Token 或登录验证码。详见[消息渠道](messaging.md)。

## CookieCloud

115 相关域名（115.com、115cdn.com、115cdn.net、115vod.com、anxia.com 及其子域）的 Cookie 不能读取或写入。显式请求这些域名会报错；较宽的选择（例如 `com`）读取和导出时也会跳过它们，既不返回也不会被覆盖或删除。

## 宿主文件操作

`ctx.files` 只处理用户选择且宿主允许的业务路径。系统文件、宿主数据与凭据仍受保护；文档不公布受保护目录的具体路径。宿主文件不能复制或移动到插件自有文件区；插件自有文件可通过允许的文件操作输出到业务目录。路径解析和权限判断由宿主统一执行，拒绝时应停止操作并向用户显示原因。

## 安装后防篡改

安装或更新时，宿主对磁盘上的代码目录计算摘要，并用保存在主数据库中的宿主密钥签名，签名写入安装记录。宿主启动、每次运行任务或处理请求、加载页面资源前都会核对（文件大小与修改时间不变时复用上次结果）：

- 任何代码文件被修改、新增或删除，或安装记录里的签名对不上，插件立即停用，状态为故障，原因“插件代码在安装后被修改”。
- 停用后数据保留，需卸载后重新安装才能恢复。
- 本功能上线前安装的插件，在首次核对时补签名，此后的修改都会被发现。

## 未覆盖的范围

插件页面与宿主同源运行。页面代码若把接口路径拆开再拼接，并绕过 SDK 直接用浏览器请求，安装扫描无法识别，宿主也无法区分请求来源。请只安装信任的作者发布的插件。
