# 本机调试与编译交付

开发和调试使用源码目录或 `check.mjs --pack` 生成的可读 `.dian115p`，通过自己管理的 DIAN115 插件中心直接导入。宿主将源码编译为本机字节码并显示“本机调试”。修改后通过更新流程重新导入，不改宿主已安装目录。该包没有正式发布资格，不能覆盖同 ID 的正式安装。

正式交付前读 [编译 MCP 契约](../assets/public-kit/encrypted-delivery.md#编译-mcp-与正式发布)：

1. 开发工具直连 `/api/openapi/v1/plugin-build/mcp`，请求头携带系统设置的 OpenAPI Key。完成 MCP 初始化并查询 `tools/list`。当前入口拒绝浏览器 Origin，不用查询串传 Key。
2. 查询 `dian115_build_environment` 的 `formal_compile_configured`、ABI、预算、账号和阻塞项。环境查询没有产物，返回 `release_ready: false` 属于正常；`release_signing: dian115-local` 表示由 DIAN115 本地签名，会员资料读取沿用现有接口。
3. 多个癫影账号由用户明确选择 `account_id`。宿主读取保存的 API Key 实时验证；不要把系统 Key、癫影 Key、会员 ID 或昵称放进工具参数或插件源码。
4. `dian115_check_plugin` 供结构、敏感调用及报告检查，不要求会员验证，不安装、不出包。`dian115_verify_build_account` 可单独确认实时会员身份。
5. 调用 `dian115_compile_plugin`，提交 `files` 或 `files_base64`，以及选定的 `account_id`。宿主先验证会员，再检查源码、真实编译和链接，完成运行/原稿独立加密，最后通过现有资料接口复核同一凭据和会员身份，并由 DIAN115 本地签名。编译和审查均不执行上传业务。
6. 仅当 `isError` 非 true、`structuredContent.release_ready: true`、存在 `package_base64` 且解码后的 SHA256 与返回值一致时，保存返回文件名并报告正式出包。Base64 只在结构化结果中返回；当前没有异步任务、进度查询或产物下载 URL。
7. 未配置材料时返回 `protection_keyring_unavailable`；会员、编译或签发失败都没有正式包。如实报告阻塞项，不伪造下载链接，不把可读打包或 v3 网页加密作为成功。

正式模块的开发者名称就是 DIAN115 本地签名绑定的会员昵称，宿主覆盖源码自填 `author`；市场 `author` 也须使用该签名昵称。昵称在新发布时更新，历史版本保留原快照。追溯用会员 ID 与发布 ID，不能依赖昵称唯一性或密钥尾号。

同一维护者审核公钥配置下，所有作者经正式流程生成的 v4 包都强制保留加密原稿审查区，维护者可离线验签并还原编译时提交的原稿，无需作者另交密钥。审核公钥由宿主确定，不让作者替换；审核私钥只在维护者本机保管，不放入插件、MCP 参数或普通主程序构建材料。仅生成密钥尚未使已发布环境生效，须实际接入主程序构建并分发。轮换后保留历史审核私钥及验签公钥，新密钥不能解开旧密钥对应的包；没有提交的原文件及提交前混淆之前的源码无法还原。

后台提交兼容引擎的 JS；先自行构建浏览器 UI，并放在独立 `ui/` 目录。`.map`、`.ts`、`.tsx`、`.jsx`、`.vue`、`.svelte` 只留在加密原稿区，不作为运行依赖。正式配置剥离函数源码，不能靠 `Function.toString()` 恢复函数正文。没有 DOM、Node 编译脚本或新业务 API。

保护与准入配置就绪后，URL/市场的新正式安装和更新要求 v4 编译包；已登记的具体历史内容仍兼容。直接管理员源码导入获得独立本机调试记录，复制已安装目录、修改 `debug`/`delivery` 标记不能晋升正式或取得另一实例的准入。未配置保护材料的兼容构建保留过渡行为，仍须按真实能力报告。

正常静态模块执行直接加载经过同一份字节认证的持久化字节码，不重复解密、解压或解析源文件。正式包在 ABI 更新时从认证原包于启动阶段重建；本机调试须重新导入。会员 Key 后续失效不增加已安装插件逐任务联网要求。

交付报告区分本地检查、本机业务调试、正式出包及真实第三方验证。编译、加密和本地来源签名都不能证明代码没有恶意行为；本地签名以宿主及内置密钥可信为前提；未运行完整 Linux 业务基准时不承诺全场景性能或内存收益。
