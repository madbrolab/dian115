# 数据生命周期

HTTP Cookie 使用宿主加密会话，不计入普通 KV；按安装和账号隔离，卸载清空。CookieCloud 的私有导入副本与对共享服务的业务写回分别处理，见 [HTTP 会话](http.md)。

业务配置、规则和业务状态通过 Host Storage 保存；页面筛选/布局等用 `api.storage`。凭据按公开绑定协议管理，持久记录保存允许的引用。`/package` 是只读包资源；页面内存和 guest 全局变量是临时状态，不能当持久数据库。不能依赖可写宿主目录、浏览器 localStorage/IndexedDB 或私有数据库表。

先设计小而明确的 JSON，例如 `{schema_version:1,rules:[...],operation_ref:"..."}`。schema_version 是业务格式版本；KV revision/ETag 是并发版本，不能混用。读取 404 表示没有配置，其他错误应展示并暂停相关写入，不能当空配置覆盖已有数据。升级需要格式变化时写明确转换及冲突处理；不增加已废弃平台协议的兼容层。

用 SDK StorageGet/Put：更新依赖已读值时发送 If-Match；412 后重新读取、合并或请用户处理，不盲目覆盖。业务尝试使用稳定幂等键；相同键必须对应相同请求。操作完成标记与业务状态尽可能在同一原子值中保存，避免通知后只依赖临时计数去重。

StorageList 只取元数据，按需读值；每次处理一页，按原 next_cursor 前进。绑定 prefix/安装及游标过期的规则见 storage-and-lifecycle.md；不要解码游标或无限积累列表。用量失败显示未知而非 0，配额统计不是数据库文件大小。所有额度从固定协议核对，不自行扩容。

首次挂载先恢复 action intent、job_ref 和页面偏好；等待期间禁用依赖这些记录的提交。读取失败提供显式重试。UI 存储请求与 runtime KV 通过宿主按安装隔离，但仍共享该安装总用量；不能伪造安装 ID 越权。

重启、停用、休眠释放后重读持久状态。卸载清空插件拥有的 UI/KV、任务、回执及安装资源，失败清理由宿主保持标记并继续；重装从空配置开始。插件不要在外部目录留下用于“卸载恢复”的影子副本。卸载不会撤销已发送通知或已修改的其他业务对象；向用户写清哪些业务会真实执行。
