# 数据与生命周期 v3

宿主数据目录下的 `extensions/<plugin-id>/`：

```text
code/<revision>/       安装的代码快照
 data/state.sqlite     加密 KV（含 settings 键）、Cookie 会话、任务、目录监听、监听端口、通知投递记录、有限 HTTP 缓存
 data/secrets.key      此次安装独立数据密钥
 data/files/           插件默认文件目录
cache/ logs/ tmp/      插件拥有的辅助目录
```

以上缩进仅为排版；目录名没有前导空格。全局 `.registry.json` 仅保留安装元数据和数值标识计数，不保存插件 Cookie、登录密码或业务输入；仓库来源地址属于平台配置，会持久保存。SQLite 按需打开，闲置一分钟关闭。除声明了 `daemon` 的[常驻任务](long-connections.md)外，没有常驻 JS VM。Cookie 热会话在无请求使用且闲置十分钟后释放内存，后续从加密数据恢复；Cookie 表与用户 KV 分开，不占用用户键名。每个插件的 Cookie/session/cache 和 KV 独立；KV 不沿用旧版总量配额，实际受可用磁盘约束。分页默认 50、最多 1000，usage 按 code/data/cache/logs/tmp 统计实际磁盘字节。

data/secrets.key 与数据库同属私有目录。磁盘加密防止误读明文，不抵抗获得完整宿主目录的管理员。代码默认保留源码；加密插件只持久保存加密代码与该版本密钥。

首次打开直接加载页面，不唤醒后台 VM。关闭页面调用 mount 返回的清理函数，并中止页面 signal；后台任务生命周期独立。停用取消任务、常驻任务、定时器、目录监听并释放监听端口，保留数据；再次启用重新恢复已登记监听、端口、调度和常驻任务。已经开始执行的任务异常中断保存 attention_required，不自动重做外部写操作；同版本 recover 处理器返回 complete、resume 或 attention。若记录明确表明尚未进入脚本（例如队列拒绝），宿主启动时可自动恢复同版本任务；后续同版本重试也可直接执行，不要求额外核对；宿主先持久化 attempted 才允许脚本开始。单个插件目录或密钥损坏会显示故障并停用该插件，不阻断其他插件；可卸载后重新安装。安装后代码目录被修改（文件改动、新增或删除，或安装记录签名不符）同样显示故障并停用，见[安全限制](security.md#安装后防篡改)。

更新保留 generation、数据和仍被声明的权限授权，切换 revision，新申请的权限默认关闭，常驻任务自动重启；不允许覆盖正在运行的任务或文件/网络操作。卸载先持久化 deleting 标记，撤销入口、取消任务与监听，等待宿主操作退出，关闭 SQLite，再删除完整目录及队列记录。请求断开后清理继续；重启会继续处理 deleting。只有目录删完并移除登记后才允许重装；重新安装生成不同 generation 和递增队列 ID，旧任务不能写回新安装。

卸载不会撤销已创建的 115 文件、宿主整理结果、已发通知、写到用户指定外部路径的文件或显式导出至共享 CookieCloud 的数据。默认 SDK 存储全部位于插件目录，不需要浏览器私有数据库。可信页面若绕过 SDK 写宿主的全局 LocalStorage、Service Worker 或全局事件，属于作者自行管理的宿主副作用；卸载无法安全识别并删除其他功能共享的数据。插件作者应使用 SDK 存储和清理函数。

KV 支持 expected_revision：首次创建传 0；不匹配返回冲突。任务 business_key 永久留在该插件历史中；需要新业务时使用新标识，不通过更换标识绕过未核对的执行结果。

后台共享异步操作默认最多同时执行 128 项，目录快照默认最多同时执行 4 项，避免为每个监听创建持续占用的执行器。忙碌的快照不会阻塞全局维护循环。运营者可通过 DIAN115_EXTENSION_IO_CONCURRENCY、DIAN115_EXTENSION_WATCH_CONCURRENCY 设置正整数调整容量；这属于宿主资源调度，不是插件权限白名单。插件脚本与宿主共用内存：运行期间存活堆比空闲基线增长超过 DIAN115_EXTENSION_MEMORY_MB（默认 512）时，宿主中止正在运行的插件脚本，任务记为失败。达到异步容量时当前调用明确失败，不会替作者无限排队或自动重试外部变更。
