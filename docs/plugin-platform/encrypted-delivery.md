# 源码保护与离线安装

本文前半部分描述旧 v3 网页加密兼容流程；后半部分说明 DIAN115 的[编译 MCP](#编译-mcp-与正式发布)、v4 正式包、本机字节码与调试规则。可读打包和旧网页加密不等于 v4 正式发布。

## 现有 v3 网页加密

作者在加密网页选择完整源码目录或可读 `.dian115p`，无需登录或口令，直接点击“开始加密”，查看调用报告后下载加密 `.dian115p`。把这个文件交给用户即可；用户直接在 DIAN115 插件中心选择文件安装。

主程序内置解密能力。安装、首次打开、休眠唤醒、后台任务和后续运行均不需要连接加密平台，不需要用户填写平台地址、运行令牌、公钥或任何密钥。平台仅用于作者加密和维护者审查，不是插件运行依赖。

每次发布随机生成 256 位内容密钥，各文件使用独立 nonce 的 AES-GCM 加密。内容密钥再由内部源码保护密钥封装；可读调用报告、插件身份和源码摘要参与完整性校验。安装包包含密文、封装后的内容密钥和报告，不包含明文解密密钥；无需公钥或签名机制。宿主在本地解密并重新分析实际代码，展示报告后由用户决定安装。

主程序的内置源码保护材料由平台维护者在构建时注入，不随 SDK、示例或公开仓库分发。插件作者和安装用户都不需要操作这些材料。主程序不下载、持久化平台返回的运行密钥，也没有在线取钥接口或失败回退。

加密服务不留档：上传源码、生成的加密包、管理员解密得到的源码都只在本次请求内存中处理，不写磁盘、数据库、对象存储或请求日志。平台不提供按发布 ID 查询源码的入口；请由作者保管源码和分发包。

管理员使用网页的“管理员解密”窗口，填写独立管理员审查令牌并上传加密 `.dian115p`。服务先验证管理员权限，再检查包内身份、完整性、摘要与文件路径，还原源码后供逐文件查看或下载源码 `.dian115p`。不需要原发布记录，也不会执行上传插件的代码。审查令牌和解密结果不写入浏览器持久存储，网页提供清除口令与结果的按钮。下载后的源码文件由管理员自行保管。

在线解密仅供人工检查是否存在恶意代码；成功解密和完整性校验不能证明代码安全。自动风险报告供辅助参考，不能替代源码审查。普通安装和运行始终使用主程序内置解密，与此管理员窗口无关。

Worker 无数据库或对象存储绑定。默认源码包上传上限 8 MiB、源码合计 16 MiB；管理员上传加密包上限为 32 MiB，以容纳加密清单及编码开销，还原源码合计仍为 16 MiB。超出返回 HTTP 413。此传输预算不改变宿主中插件的存储或网络能力。

平台拒绝可识别的主项目专有源码标记和模块引用，不因作者使用 frontend/src 等正常工程目录而拒绝。源码包不应包含真实用户密码、Cookie、私钥或主项目源码。自动分析不能证明代码归属或覆盖所有动态访问，安装时仍展示未确定范围。

为了避免把后台源码作为页面资源返回，加密插件的 UI 使用独立目录（例如 ui/），后台代码和工程源码放在该目录之外。完整示例已采用此结构。加密用于保护分发包中的源码；主程序执行和浏览器显示仍需要解密，不能承诺阻止拥有宿主运行权限的人观察运行代码。

插件包结构见 [包格式](package-format.md)。卸载清空该插件在宿主内的全部默认数据；加密平台没有该插件的留档。

## 编译 MCP 与正式发布

2026-11-02 本地实现状态：已接入持久化后台字节码、v4 加密出包、DIAN115 本地内容签名、本机调试登记、安装防篡改和独立原稿审查。正式链路需要维护者给主程序注入 v4 保护配置。编译、加密、签名和安装验签均由 DIAN115 完成；会员资料读取沿用现有接口，不增加插件签发、查询或存储接口。未配置材料时不生成正式包，旧插件仍可使用原有兼容加载器。

### 身份与开发者名称

| 凭据 | 使用方与职责 |
| --- | --- |
| 系统设置中的 OpenAPI Key | 开发工具连接本机编译 MCP，放在请求头 |
| 癫影账号配置中的 API Key | 宿主通过现有接口实时查询会员身份及昵称 |
| DIAN115 内置运行根密钥 | 私有构建注入；分离派生运行加密材料和本地发布签名材料 |
| 维护者审查私钥 | 仅在独立审查环境，还原原始源码 |

开发工具只传账号选择 `account_id`，不读取或向工具参数提交癫影 API Key。多账号必须明确选择；只有一个可用账号时可省略。不自动切换默认分享账号、不使用缓存昵称。不增加 VIP、积分消费、开发者注册或人工审批条件。

**正式模块展示的开发者名称就是会员昵称。** DIAN115 出包前通过现有接口复核同一会员，随后在本地签名绑定昵称快照；安装时覆盖源码自填的 `author`。昵称变更在下一次新发布生效，不重写历史签名。昵称可重复、可改变，追责定位使用会员唯一 ID 和发布 ID。包、报告和日志不包含系统 Key、癫影 Key 或激活密钥尾号。

### MCP 连接

地址：`/api/openapi/v1/plugin-build/mcp`。使用请求头 `Authorization: Bearer <系统 OpenAPI Key>` 或 `X-OpenAPI-Key: <系统 OpenAPI Key>`。通过网络连接时使用 HTTPS，客户端不得把系统 Key 交给插件页面。

采用无会话的 Streamable HTTP JSON 响应。支持 `initialize`、初始化通知、`ping`、`tools/list`、`tools/call`。默认协议 `2025-06-18`，也接受 `2025-03-26`；后续请求带协商的 `MCP-Protocol-Version`。请求使用 `Content-Type: application/json`，客户端接受 `application/json, text/event-stream`。没有 GET SSE 流、DELETE 会话和 JSON-RPC 批处理。

入口供开发工具直接连接，拒绝带 Origin 的浏览器请求；不接受查询串 Key、CookieCloud 头或管理员 JWT 替代系统 Key。每次 HTTP 请求重新读取系统 Key。编译管理接口不属于插件业务 API，已安装插件的调用上下文和标记均被拒绝；安装扫描也拒绝引用该管理路径。

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `dian115_build_environment` | 无 | 编译器 ABI、预算、无凭据的账号列表、`formal_compile_configured`、阻塞项 |
| `dian115_verify_build_account` | 可选 `account_id` | 实时会员 ID、昵称、验证时间；不是长期编译许可 |
| `dian115_check_plugin` | `files` 或 `files_base64` | 结构、受限调用与报告，供本机调试，不安装、不出包 |
| `dian115_compile_plugin` | `files` 或 `files_base64`，可选 `account_id` | 验证会员、真实编译检查、加密、最终会员复核、本地签名及正式产物 |

`files` 是“工程内相对路径 → UTF-8 内容”；包含二进制时使用 `files_base64`，值是标准 Base64。二者只能选一项。不接受服务器目录、远程源码 URL、自填会员身份、密钥或调试绕过参数。编译不执行上传工程的业务代码或构建脚本。

请求体及源码总预算各为 16 MiB，最多 4096 个文件，共享一个处理槽，繁忙返回 `build_busy`，本次处理上限 120 秒，产物不超过 40 MiB。Base64/JSON 的编码开销也计入请求体预算。此预算不改变插件业务能力。

```json
{
  "jsonrpc": "2.0", "id": 1, "method": "tools/call",
  "params": {
    "name": "dian115_compile_plugin",
    "arguments": {
      "account_id": "所选本地癫影账号ID",
      "files": {
        "plugin.json": "{\"schema_version\":3,\"id\":\"example.build\",\"name\":\"示例\",\"version\":\"1.0.0\",\"jobs\":[{\"id\":\"run\",\"entry\":\"jobs/run.js\"}]}",
        "jobs/run.js": "export async function run(ctx) { return 42 }"
      }
    }
  }
}
```

结果同时包含 `content` 和 `structuredContent`；失败以 `isError: true` 表示，HTTP 200 不代表成功。正式成功须同时满足非错误结果、`structuredContent.release_ready: true` 及有效的 `package_base64`。客户端解码该字段，核对 `sha256`，保存为返回的 `.dian115p` 文件名。Base64 只在结构化结果出现一次；没有异步编译任务或下载路由，不能猜测下载地址。

环境查询的 `release_ready: false` 表示尚未签发某个产物，不等于编译器不存在。`formal_compile_configured` 反映本机保护与签名配置；会员 Key 仍须通过实时校验。缺少保护材料返回 `protection_keyring_unavailable`；本地签名失败、Key 中途更换、账号删除/停用、身份或最终签名不匹配时都不返回包。

### 正式包、编译与完整性

```text
系统 Key 鉴权 → 实时验证会员 Key → 冻结源码
→ 检查原稿 → 生成运行输入 → 真实后台模块编译与链接
→ 分别压缩、认证加密运行区与原稿审查区
→ 通过现有接口复核同一会员 Key 与昵称 → DIAN115 本地签名、验签 → 返回正式包
```

v4 格式名为 `dian115-protected-v4`，后缀仍为 `.dian115p`，ZIP 容器严格只有三个对象：`release.json`、`runtime.bin`、`review.bin`。头部包含描述符、调用报告和 DIAN115 本地来源签名（`issuer: dian115-local`）。宿主签署整个描述符摘要，绑定会员 ID、昵称、发布 ID、插件 ID/版本、原稿/运行输入/报告/两份密文摘要、编译配置及全部封装参数；本地签名材料由内置运行根按独立 HKDF 用途派生，公钥由维护者注入并固定，不能接受插件提供的替代信任根。

每次发布使用新的 32 字节随机盐、32 字节内容密钥及 12 字节 nonce，通过 HKDF-SHA256 分离用途，运行区和密钥封装使用 AES-256-GCM。原稿审查区通过独立维护者 X25519 公钥协商秘密，再派生 AES-GCM 密钥。盐不是秘密，不靠隐藏算法抵抗逆向。v4 运行材料与旧 v3 密钥独立。

运行输入不包含 `.map`、`.ts`、`.tsx`、`.jsx`、`.vue`、`.svelte` 开发材料；这些保留在原稿审查区。先自行构建浏览器 UI，后台提交引擎支持的 JS；不能直接导入上述原稿扩展名作为后台执行依赖。普通业务数据保持原路径与字节。UI 使用独立目录，例如 `ui/`，浏览器资源可被使用者观察，不能把业务秘密放入 UI。

宿主安装时验签、解密、再次审查实际运行输入，在受信本机生成真实持久化字节码，并绑定本机准入记录与封印。后台源码不保留为可执行目录中的明文文件。完整加密包仅用于认证后的引擎 ABI 升级重建；普通任务不解密、解压或重新解析静态源码，不保留跨任务源码/AST 全文缓存。每个任务仍使用独立运行实例，业务 API 和外部平台调用不变。

直接加载采用私有指令序列及去源码信息的编译配置，去除函数源码和源码映射；不是把压缩源码改后缀。依赖 `Function.toString()` 取得原函数正文的后台逻辑不适合此配置。动态 `eval` 仍须在执行时解析其输入，不属于预编译静态模块。

每次使用模块或资源时对实际读取字节计算摘要，再将同一份已验证字节交给加载器，不能仅依靠大小/修改时间。修改密文、来源、报告、入口、字节码或安装登记不能得到有效内容；发现改动后停用。新增未登记模块不可执行。防篡改基于官方宿主、内置根密钥与独立准入存储可信。取得宿主运行根密钥的人也能派生本地签名材料；本地来源记录不能作为独立会员服务的签名证明，不能承诺控制宿主后仍绝对不可伪造。

插件元数据随正式包保存，会员资料接口只接收既有身份查询请求，不接收源码、摘要或发布 ID，也不新增服务器记录。维护者可用单文件离线审核网页，在浏览器加载插件包、审核私钥与独立保存的验签公钥，先验签再还原原始工程。网页支持文件筛选、行号预览及完整源码 ZIP 下载；源码只作为文本读取，不执行插件，不联网、不保存密钥或源码到浏览器持久存储。旧版 v3 使用对应的源码保护密钥，可读源码包无需密钥；缺少历史密钥时无法还原对应加密版本。原有命令行审查工具仍可使用。编译、来源认证和成功解密都不能证明没有恶意代码。

统一审核范围是所有通过配置了维护者同一审核公钥的 DIAN115 正式编译流程生成的 v4 包，与插件作者无关。正式编译强制保留加密原稿审查区，维护者使用对应审核私钥及独立保存的验签公钥还原，无需向每个作者索取解密密钥。审核公钥由宿主配置提供，不接受作者为单个插件指定替代公钥。

该规则须在保护配置实际接入主程序构建、并分发给开发者使用后生效；单独生成密钥不会改变已发布的编译环境。还原范围是作者提交给编译流程的完整原稿，不能恢复从未提交的文件或提交前混淆之前的源码。密钥轮换后须保留历史审核私钥与验签公钥；新密钥不能解开使用其他密钥生成的旧包。

### 本机调试与旧插件

实例管理员通过插件中心直接上传源码包或导入本机源码目录，获得 `local-debug-bytecode` 安装；宿主安装时编译并登记，界面显示“本机调试”。不通过包内 `debug: true`、昵称或客户端 IP 授予资格。源码可以复制；复制已安装调试目录及插件注册文件到另一实例不能取得准入，需由另一实例管理员重新导入。

URL 和市场走正式检查入口。在保护配置和准入存储就绪后，新正式安装及更新必须使用 `protected-v4`；源码调试不能上架，不能覆盖同 ID 的正式安装，不能改标记晋升为正式发布。`pack.mjs` 和 skill 的 `check.mjs --pack` 只生成源码调试容器或编译输入。

升级时对现有旧插件核验并登记具体内容摘要，保持原有加载方式。仅该实例已登记的相同历史内容继续兼容；旧日期、旧 ID、低版本号都不能让新源码获得正式资格。没有全网历史包白名单，新设备上的未登记旧包需要重新正式编译，或由管理员作为本机调试导入。

保护材料尚未注入的兼容构建不强制切换正式新格式；开发工具必须查询实际环境，不能把这个过渡状态当作正式出包成功。正式字节码的 ABI 改变时从认证原包在启动阶段重建；本机调试需重新导入源码，不回退执行未认证源文件。

模块加载微基准已包含本机文件读取、实际字节认证和链接；具体结果及限制由维护者记录。它不能代替 Linux 完整任务的 CPU、常驻内存、RSS 和尾延迟验收，不能宣称所有插件都零开销或等比例提速。
