# 数据与生命周期 v3

宿主数据目录下的 `extensions/<plugin-id>/`：

```text
code/<revision>/       安装的代码快照
 data/state.sqlite     加密 KV（含 settings 键）、Cookie 会话、任务、目录监听、监听端口、通知投递记录、有限 HTTP 缓存
 data/secrets.key      此次安装独立数据密钥
 data/files/           插件默认文件目录
cache/ logs/ tmp/      插件拥有的辅助目录
```

以上缩进仅为排版；目录名没有前导空格。全局 `.registry.json` 仅保留安装元数据和数值标识计数，不保存插件 Cookie、登录密码或业务输入；仓库来源地址属于平台配置，会持久保存。SQLite 按需打开，闲置一分钟关闭。除声明了 `daemon` 的[常驻任务](long-connections.md)外，没有常驻 JS VM。Cookie 热会话在无请求使用且闲置十分钟后释放内存，后续从加密数据恢复；Cookie 表与用户 KV 分开，不占用用户键名。每个插件的 Cookie/session/cache 和 KV 独立；KV 不沿用旧版总量配额，实际受可用磁盘约束。分页默认 50、最多 1000，usage 按 code/data/cache/logs/tmp 统计实际磁盘字节。

data/secrets.key 与数据库同属私有目录。磁盘加密防止误读明文，不抵抗获得完整宿主目录的管理员。代码默认保留源码；加密插件只持久保存加密代码与该版本密钥。

首次打开直接加载页面，不唤醒后台 VM。关闭页面调用 mount 返回的清理函数，并中止页面 signal；后台任务生命周期独立。停用取消任务、常驻任务、定时器、目录监听并释放监听端口，保留数据；再次启用重新恢复已登记监听、端口、调度和常驻任务。已经开始执行的任务异常中断保存 attention_required，不自动重做外部写操作；同版本 recover 处理器返回 complete、resume 或 attention。若记录明确表明尚未进入脚本（例如队列拒绝），宿主启动时可自动恢复同版本任务；后续同版本重试也可直接执行，不要求额外核对；宿主先持久化 attempted 才允许脚本开始。单个插件目录或密钥损坏会显示故障并停用该插件，不阻断其他插件；可卸载后重新安装。安装后代码目录被修改（文件改动、新增或删除，或安装记录签名不符）同样显示故障并停用，见[安全限制](security.md#安装后防篡改)。

更新保留 generation、数据和仍被声明的权限授权，切换 revision，新申请的权限默认关闭，常驻任务自动重启；不允许覆盖正在运行的任务或文件/网络操作。卸载先持久化 deleting 标记，撤销入口、取消任务与监听，等待宿主操作退出，关闭 SQLite，再删除完整目录及队列记录。请求断开后清理继续；重启会继续处理 deleting。只有目录删完并移除登记后才允许重装；重新安装生成不同 generation 和递增队列 ID，旧任务不能写回新安装。

卸载不会撤销已创建的 115 文件、宿主整理结果、已发通知、写到用户指定外部路径的文件或显式导出至共享 CookieCloud 的数据。默认 SDK 存储全部位于插件目录，不需要浏览器私有数据库。可信页面若绕过 SDK 写宿主的全局 LocalStorage、Service Worker 或全局事件，属于作者自行管理的宿主副作用；卸载无法安全识别并删除其他功能共享的数据。插件作者应使用 SDK 存储和清理函数。

KV 支持 expected_revision：首次创建传 0；不匹配返回冲突。调用方提交的任务 business_key 永久留在该插件历史中；需要新业务时使用新标识，不通过更换标识绕过未核对的执行结果。宿主自动发起的运行（定时 `schedule:`、宿主事件 `host:`、目录监听 `watch:`、消息 `message:`、按钮回调 `callback:`）标识按次唯一，结束超过 30 天后连同日志删除，避免每分钟一次的定时任务一年积累数十万条记录；需要长期留存的结果请自行写入 storage。

后台普通任务默认最多同时执行 4 个，所有插件的 HTTP 脚本另共用 4 个执行名额；等待名额时不创建 JS VM，HTTP 请求也不提前缓冲请求体。两类执行名额相互独立，常驻任务单独运行，避免长连接阻塞普通任务。等待过程计入任务或 HTTP 处理器超时，取消、停用、卸载会终止等待；普通任务取得名额并保存 attempted 后才进入脚本。HTTP 每插件最多接纳 32 个请求（含等待），超过时返回 503。运营者可通过 DIAN115_EXTENSION_TASK_CONCURRENCY、DIAN115_EXTENSION_HTTP_CONCURRENCY 设置正整数调整执行名额；设为 1 可进一步压低并行执行的资源峰值。

后台共享异步操作默认最多同时执行 128 项，目录快照默认最多同时执行 4 项，避免为每个监听创建持续占用的执行器。忙碌的快照不会阻塞全局维护循环。运营者可通过 DIAN115_EXTENSION_IO_CONCURRENCY、DIAN115_EXTENSION_WATCH_CONCURRENCY 设置正整数调整容量；这属于宿主资源调度，不是插件权限白名单。达到异步容量时当前调用明确失败，不会替作者无限排队或自动重试外部变更。

空闲时停止脚本内存采样；数据库、Cookie 会话、安装预览和目录监听共用按最近到期时间唤醒的维护器，无活动资源时停止计时。目录无变化或重复出现同一错误时不重复保存快照，扫描间隔和实时事件补偿规则保持不变。任务状态通过数据库索引查询，旧记录首次打开时自动补齐索引；任务输入、检查点、结果和日志继续加密保存。日志按行追加到独立的日志表，任务记录本身保持很小，进度刷新不再重写整段日志；旧版本嵌在记录里的日志在下次写入时自动迁移。进度与日志最多每 500 毫秒合并落盘，检查点、进入脚本前的 attempted 标记和最终状态立即保存；宿主任务队列仍实时收到进度。插件数据库使用 WAL 与 synchronous=NORMAL：宿主崩溃不会丢失或损坏已提交的数据，只有整机断电可能丢失最后几次提交。已结束超过 30 天的任务在数据库打开时及之后每天清理一次（分批进行，不长时间占用数据库）：自动发起的运行整条删除，调用方提交的运行只删日志，记录、结果和 business_key 去重保持不变。

每次运行只为用到的标准库付费：URL、fetch/Headers/Response、TextEncoder/TextDecoder、WebSocket、ctx.codec/crypto/html/xml、ctx.ws/tcp/http.stream 在第一次访问时才构建，用法不变。一次空运行的宿主开销约 0.3 ms、0.2 MB 临时内存。

加密发行包（encrypted.json）按文件版本只读取、解析和解开密钥一次，之后页面资源和后台模块直接解密所需文件；文件被改写后重新打开并校验，闲置 10 分钟释放，总量 32 MiB。

插件代码在首次运行时读取、校验、解析和编译一次，之后所有运行（定时、事件、页面、HTTP 处理器）共用这份结果，每次运行只创建自己的脚本环境。一个约 180 KB 的插件，每次运行因此少花约 28 ms。已编译安装包每次运行仍会重新核对文件摘要，代码被改动即停用。插件空闲 10 分钟后释放这部分内存（仍有常驻任务或长任务在运行的插件不释放，因为代码仍被使用）；总量超过 DIAN115_EXTENSION_CODE_CACHE_MB（按估算堆，默认 64）时先释放最久未用的插件。

插件脚本与宿主共用内存：运行期间存活堆比空闲基线增长超过 DIAN115_EXTENSION_MEMORY_MB（默认 512）时，宿主中止正在运行的插件脚本，任务记为失败。无限递归在 10000 层调用时就地失败，不会触发这项全局保护。这是共享堆增长的软保护，不是每插件预留内存或独立硬上限，也不包含 Chromium 子进程。

队列显示由清单顶层 queue（API 3.12，默认 true）和各 job.queue 共同决定。同一安装的可见后台运行与页面文件操作合并显示，隐藏任务不参与汇总。合并仅作用于列表、SSE 和详情视图，各次执行的上下文、结果、取消与持久历史仍独立；清除合并条目不删除插件内历史。队列只保留近期内存记录，汇总计数不是永久累计次数。
