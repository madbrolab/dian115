# .dian115p 插件包

插件的交付、下载和安装文件统一使用 `.dian115p`，媒体类型为 `application/vnd.dian115.plugin`。可读源码包与加密包使用相同后缀，由包内清单判断交付类型；用户不需要手工改名。

容器使用标准 ZIP 编码以复用成熟的压缩与校验实现；这属于格式内部细节，不把 `.zip` 作为产品中的插件安装格式。根目录不能再套一层工程文件夹。

可读源码包包含 `plugin.json` 和完整运行资源，例如 `ui/page.js`、`jobs/job.js`。插件作者可以在加密网页选择源码目录，由浏览器直接打包上传；也可用无第三方依赖的工具生成可读包：

```sh
node conformance/pack.mjs /绝对路径/插件源码 /绝对路径/输出/插件.dian115p
```

输出放在源码目录之外。工具忽略 `.git`、`node_modules`，拒绝软链接，并保留普通业务资源目录。不要将真实凭据、私钥或主项目源码放进插件工程。

上述工具只生成可读源码容器，可用于自己的设备安装调试或作为编译输入，不会产生编译证明。新格式正式发布经 DIAN115 编译 MCP 实时验证会员并完成编译、保护和出包；成功结果返回 `package_base64` 与摘要，未配置保护材料或签发失败时没有产物。旧 v3 加密格式与新格式实施状态见[编译与交付](encrypted-delivery.md#编译-mcp-与正式发布)，不能因同为 `.dian115p` 就认定已编译。

旧 v3 加密包只包含 `encrypted.json`：可读调用报告、发布 ID、代码与源码摘要、封装后的内容密钥和逐文件密文。主程序使用内置能力在本地完成完整性校验、解密与再次分析，展示报告后由用户确认安装。没有公钥、在线取钥或平台连接配置。

管理员上传加密包并验证权限后，可解密下载源码 `.dian115p`。文件路径与每个文件的原始字节保持一致，压缩容器重新生成；平台不保存源码或插件包，也不能按发布 ID 取回源码。主项目运行目录内的插件数据遵循卸载清空规则。


v4 正式编译包严格包含 `release.json`、`runtime.bin`、`review.bin`，不接受附加文件。头部 DIAN115 本地来源签名绑定会员身份、全部内容与封装参数；正式开发者名称取签名中的会员昵称。后台运行区与维护者原稿审查区独立加密。安装时在受信本机生成并封印与当前引擎 ABI 匹配的持久化字节码；日常运行直接加载已认证字节。具体规则见[编译与交付](encrypted-delivery.md#编译-mcp-与正式发布)。

插件清单仍使用 `schema_version: 3`，v4 是交付封装版本，不修改第三方业务 API。源码直接导入属于本机调试，不能把 `debug` 字段写进包来获取正式资格。
