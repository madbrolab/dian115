部署 DIAN115

在 Linux / NAS 上使用 Docker Compose 启动 DIAN115，再配置网盘服务、115 账号、媒体目录与播放连接。数据库可选择 SQLite 或 PostgreSQL。

开始前先阅读CloudDrive2 部署与接入CD2、DIAN115 与 Emby 路径搭配

1. 首次配置的四步顺序

01 准备与部署：Linux / NAS 优先推荐 Host 网络。先部署 CloudDrive2，规划 shared / rslave 挂载与媒体目录，再用推荐的 Host 配置启动 DIAN115。使用需验证的资源站时，按需加入 FlareSolverr。
02 账号与连接：初始化管理员与授权，添加 115 主账号。配置 CD2 地址与 API Token，自动读取 /CloudNAS/CloudDrive，并选择主账号实际对应的云盘。
03 媒体与规则：测试整理与分类，按需要生成 STRM。选择 RAVE 或已有 Emby 扫描媒体；用媒体库管理工具预览分类建库，再验证播放。
04 自动化与扩展：按需加入 PT、下载器、订阅、通知、音乐与 AI。共享给其他用户时，再配置门户、访问线路与邀请码。
Linux / NAS 默认按官网 Host 方案回答；用户明确需要网络隔离时再给桥接备选。使用 AURA 时按实际文件服务方案，跳过 CD2 专属部署步骤。

2. 部署前

准备 Linux / NAS、Docker Engine 和 Compose v2。先部署 CD2，确认 /dev/fuse 可用和宿主机支持共享挂载，再为 DIAN115 与 Emby 规划一致的目录。AURA 用户可按自身部署方案连接文件服务。 CloudDrive2 完整部署见前置主题 部署 DIAN115-cd2，三套容器路径见 部署 DIAN115-paths。

3. 选择 SQLite 或 PostgreSQL

不配置数据库环境变量时使用 SQLite；新装 PostgreSQL 只需数据库类型和直接连接串。已有 SQLite 数据先停止实例并运行迁移脚本，再以 PostgreSQL 启动。数据库安装、迁移和维护见独立主题 使用 PostgreSQL 新装 DIAN115、把旧 SQLite 数据迁移到 PostgreSQL 与 查看和维护当前数据库；普通首次部署仍可使用以下 SQLite 示例。

4. 推荐部署：Host 网络

将下方配置保存为 compose.yml，按实际目录修改 volumes。network_mode: host 让 DIAN115 直接使用宿主机网络，无需添加 ports。Web 管理端默认 8095，Emby 代理与音乐服务使用各自在页面中配置的端口；多个实例应设置不同端口。

配置 / 命令
services:
  dian115:
    image: madbrolab/dian115:latest
    container_name: dian115
    restart: unless-stopped
    network_mode: host
    environment:
      - PORT=8095
      - TZ=Asia/Shanghai
    volumes:
      - ./config:/config
      - ./dian115AI:/dian115AI
      # 替换为自己的宿主机目录
      - /mnt/user/media:/媒体库
      - /mnt/cache/CloudNAS:/CloudNAS:rslave

5. 目录与持久化

/config 保存账号、授权和配置；/dian115AI 保存 AI 工作区。示例将 /mnt/user/media 映射为 /媒体库，将 /mnt/cache/CloudNAS 映射为 /CloudNAS:rslave；这两项在 Emby 中保持一致。Host 网络处理网络连接，shared / rslave 处理文件挂载传播，两项都需要正确配置。

6. 启动与初始化

在 compose.yml 所在目录执行下方命令，访问 http://服务器IP:8095。初始化管理员密码并激活授权；连接 CD2、自动读取挂载点，再从文件管理确认挂载目录可读。 首次尚未设置密码时填写密码与确认密码，无默认用户名或密码；由用户自行完成。

配置 / 命令
mkdir -p config dian115AI
docker compose pull dian115
docker compose up -d dian115
docker compose ps
docker compose logs --tail=200 dian115

7. FlareSolverr 按需接入

使用 UIndex 等需要 Cloudflare 验证的来源时，再部署 FlareSolverr。按教程将同机服务的 8191 映射到宿主机 127.0.0.1，在系统设置的“FlareSolverr 过盾设置”填写 http://127.0.0.1:8191，保存并测试。普通网盘挂载与播放不依赖它。 需要完整 Compose、启动命令和其他网络场景时查询主题 部署 DIAN115-flaresolverr。

8. 备选部署：桥接网络

需要 Docker 网络隔离时，可用下方完整配置替换 Host 配置，仍保存为 compose.yml。桥接模式不设置 network_mode: host，需要逐个映射实际使用的代理和音乐端口。127.0.0.1 指向 DIAN115 容器自身；同一桥接网络的 FlareSolverr 使用 http://flaresolverr:8191，CD2 等其他服务按实际内网地址连接。

配置 / 命令
services:
  dian115:
    image: madbrolab/dian115:latest
    container_name: dian115
    restart: unless-stopped
    ports:
      - "8095:8095"
      - "8098:8098" # 第一个 Emby 代理实例，按实际配置调整
      # - "8111:8111" # 启用 RAVE 时按实际配置映射
      # - "4534:4534" # 保留原音乐协议服务时按需映射
    environment:
      - PORT=8095
      - TZ=Asia/Shanghai
    volumes:
      - ./config:/config
      - ./dian115AI:/dian115AI
      # 替换为自己的宿主机目录
      - /mnt/user/media:/媒体库
      - /mnt/cache/CloudNAS:/CloudNAS:rslave

9. 验收与备份

测试小范围整理、STRM 输出与 Emby 播放，确认 CD2 重启后目录仍可见。升级前备份完整 /config；AI 工作区有内容时一同备份。

10. 账号与连接：接通云端

初始化管理员与授权后，在系统设置选择实际使用的 CD2 或 AURA，填写真实 API 地址与 Token；CD2 保存后自动读取实际最终挂载点，例如 /CloudNAS/CloudDrive。测试、保存并按页面提示重启。添加 115 主账号，选择它实际对应的 CD2 云盘，配置转存、离线与秘享目录，再从文件管理确认目录可读。

11. 媒体与规则：先让一部作品播放

先选一个小目录测试整理、命名与分类，再按需要少量生成 STRM。官网示例 STRM 输出为 /媒体库/strm，Emby 使用同一路径扫描；已有路径不同时先核对路径转换。我的媒体 → 控制中心连接 Emby 后端、API Key 与独立代理端口，再用一部作品验证读取、输出、扫描和播放。RAVE 是官网列出的另一选择，具体配置仍遵循该主题的现有说明范围。验证成功后再开启同步并扩大目录。

12. 自动化与扩展：按需逐步启用

首次播放成功后，再按需接入 PT、下载器、订阅、通知、音乐与 AI；先验证连接和一条任务，再扩大自动化。通知按各渠道独立配置。

13. 更新与回退

升级前备份完整 /config，AI 工作区有内容时一同备份，保存当前 compose.yml 和运行镜像摘要。latest 为浮动标签，按实际发布确认版本；在原部署目录拉取并重建，保留回退镜像和持久数据。

配置 / 命令
docker compose pull dian115
docker compose up -d dian115
docker compose ps
docker compose logs --tail=200 dian115
